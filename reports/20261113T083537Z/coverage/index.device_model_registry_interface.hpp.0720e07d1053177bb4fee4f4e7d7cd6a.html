18 /// \brief Receives the writes to the variables of a runtime owner
19 class VariableValueProvider {
20 public:
21 virtual ~VariableValueProvider() = default;
22
23 /// \brief Applies \p value to \p attribute of \p variable on \p component at the owner. Called without the
24 /// DeviceModel lock on the thread of the caller, a SetVariables.req for example, which waits for it: DeviceModel
25 /// sets no deadline, so a provider answers in time itself, well within the message timeout of the CSMS, and
26 /// rejects a write it cannot complete by then. Calls are not serialised, also not for one variable.
27 ///
28 /// Accepted means that the owner applied exactly \p value: DeviceModel then stores it in memory, so the owner does
29 /// not report it. An owner that would apply another value, a clamped one for example, rejects the write.
30 /// RebootRequired means that the owner holds \p value for the next start and registers with it then. DeviceModel
31 /// keeps the value in effect until then, and so must the owner: it does not report the held value with
32 /// notify_value_changed before the next start.
33 ///
34 /// DeviceModel stores an accepted value once this call returned. When writes to one variable overlap, the value
35 /// stored last stays in memory.
36 /// \param source The source of the value (e.g. 'csms', 'internal')
37 virtual SetVariableStatusEnum set_value(const Component& component, const Variable& variable,
38 AttributeEnum attribute, const std::string& value,
39 const std::string& source) = 0;
40 };

94 /// \brief Lets owners other than the component config add components to the device model at runtime. Registered
95 /// structure is held in memory only.
96 class DeviceModelRegistryInterface {
97 public:
98 virtual ~DeviceModelRegistryInterface() = default;
99
100 /// \brief Registers \p components under \p owner and replaces all previous entries for this owner. A variable
101 /// that is no longer registered, because it is left out or rejected, loses its monitors and stored values;
102 /// unregister_components keeps them. The variable listeners are notified of each Actual value that changed.
103 /// Every variable has one definition: a variable that the component config or another runtime owner defines
104 /// already is rejected, and so is a second definition in \p components. Also rejected are a variable with an empty
105 /// instance or of a component with an empty instance or an EVSE or connector id of 0, the reserved owners
106 /// VARIABLE_OWNER_COMPONENT_CONFIG and VARIABLE_OWNER_OCPP_STACK, and the variables that libocpp writes from its
107 /// own state, see RegistrationRejectionReason::ReservedVariable.
108 /// \param provider Receives the writes to the registered variables. Without a provider, writes are applied to the
109 /// model like writes to any other variable. A write that is in progress while \p owner registers again is not
110 /// stored, the registered value stays. DeviceModel shares the ownership of the provider until \p owner is
111 /// unregistered or registers with another provider, and until the calls to it in progress return; unregistering
112 /// and registering with another provider wait for the calls in progress, unless they are called from a call to a
113 /// provider, see unregister_components. Registering with another provider does not wait for the writes that reach
114 /// that provider already. A caller that waits must not hold a lock that set_value of the provider it waits for
115 /// takes.
116 virtual ComponentRegistrationResult register_components(const std::string& owner,
117 const std::vector<RegisteredComponent>& components,
118 std::shared_ptr<VariableValueProvider> provider) = 0;
119
120 /// \brief Removes everything that \p owner registered. The monitors and stored values of its variables are kept
121 /// for its next registration. Returns once the calls to the provider of \p owner in progress returned. A provider
122 /// may call it from its set_value: called from a call to any provider, it returns at once without waiting, since
123 /// two such calls waiting for each other would never return; the provider stays alive until its calls return. The
124 /// reserved owners are ignored.
125 virtual void unregister_components(const std::string& owner) = 0;
126
127 /// \brief Reports a value that \p owner of a registered variable changed itself. Updates the model in
128 /// memory and notifies the variable listeners; the provider is not called. The value must fit the data type and
129 /// the allowed values of the variable, otherwise it is rejected. minLimit and maxLimit are not checked: they bound
130 /// what the CSMS may set, not what the owner reports. The reserved owners are rejected.
131 ///
132 /// A report made while a write to the same attribute is in progress is overwritten when DeviceModel stores that
133 /// write, after set_value returned. An owner whose change must outlast the write reports it after set_value
134 /// returned.
135 virtual SetVariableStatusEnum notify_value_changed(const Component& component, const Variable& variable,
136 AttributeEnum attribute, const std::string& value,
137 const std::string& owner) = 0;
138 };
