14 // ISO 15118-3 9.4 CM_VALIDATE BCB-toggle validation, owned by the Matching sub-machine.
15 //
16 // The EV proves it sits on the same Control-Pilot wire by switching its CP B->C->B (a "toggle") a
17 // number of times. The exchange has two steps, distinguished by the REQ's pilotTimer field:
18 // step 1 (pilotTimer == 0): the EVSE answers CM_VALIDATE.CNF result=READY(0x01), toggle_num=0, and
19 // arms the observation. If the EV sends no step 2, the EVSE autonomously repeats the step-1 CNF
20 // every TT_match_sequence, limited to C_EV_match_retry repetitions, then FAILS silently.
21 // step 2 (pilotTimer != 0): the EV sends the REQ carrying TP_EV_vald_toggle (pilotTimer, 100 ms
22 // units) and then performs its BCB toggles during that window. Per ISO 15118-3 the EVSE waits out
23 // the window and only THEN answers result=SUCCESS(0x02) with toggle_num = number of toggles seen.
24 // EvseManager counts one B->C edge per BCB toggle into ctx.bc_transition_count via the slac count_bc
25 // command, so the delta over the window is the toggle count. A step-2 REQ from the owner carrying a
26 // non-READY result is the EV's decision to terminate/skip -> no CNF. A step-1 REQ from a different EV
27 // while a validation is in progress is answered NOT_READY(0x00) (processing blocked, [V2G3-M09-13] /
28 // CmValidate_009).
29 //
30 // Driven by the Matching sub-machine: handle_req() for every CM_VALIDATE.REQ, and tick() on the
31 // update tick whenever needs_service() says the armed timer expired. reset() on entering Matching.
